# NNNN：「字體大小」改为五档 1.06／1.12／1.18／1.24／1.30，最大仍是 1.3；去掉预览，改为换档后问一句「會唔會太大／太細」可一键返回（编号待 Junyu 给）

- 日期：2026-10-19
- 状态：提议中（Junyu 10/19 提出）
- 影响范围：pilot / phase_b × 两组（两组完全相同）
- 相关代码：分支 `claude/zealous-fermat-8rgqtg`；`lib/app/app_settings.dart`（`AppFontScale`、`combinedTextScale`）、`lib/app/app.dart`、`lib/features/settings/presentation/pages/settings_page.dart`（`_FontScaleCard`、`_FontSizeCheck`）

## 背景

原来「自己 → 字體大小」只有三档：標準 1.0、大 1.15、特大 1.3。10/15 起，手机系统字体 × App 字号合起来最多 1.3 倍，避免大字把页面挤爆。Junyu 10/19 觉得三档跳得太大、按钮难看，要五档；同时认为 1.3 已经很大，不要再往上加。另外，换档后整个 App 立刻变，卡片下面的预览句子没有用。

## 决定

1. 五档平均分布：標準 1.06、稍大 1.12、大 1.18、較大 1.24、特大 1.30。
2. 封顶不变：手机系统字体 × App 字号合起来最多 1.3。
3. 手机里已存的选择按名字对应：原「標準」1.0 → 新「標準」1.06；原「大」1.15 → 新「大」1.18；原「特大」1.3 不变。所以**没改过设定的人，字会比现在大 6%**。
4. 五个按钮自己不跟字号变大（每个按钮写一个逐档变大的「字」加档名），五个一行放得下。
5. 去掉预览句子。换档后，按钮下面出现一个小框：变大时问「字大咗。會唔會太大？」，变细时问「字細咗。會唔會太細？」；两个按钮「太大（太細），返回『原来档名』」和「啱啱好」。可以不理它；离开页面就不再出现。
6. 每档哪些页面装不下，用 `test_manual/ui_text_scale_sweep_test.dart` 加 `--dart-define=SWEEP_SCALES=1.06,1.12,1.18,1.24,1.3` 扫，结果记在 `docs/history.md` 当天那一段。CI 仍扫 1.0 和 1.3。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 维持三档，只改按钮样式 | 档距太大 |
| 再加「超大」1.45、「最大」1.6（10/19 先做过一版） | Junyu：1.3 已经很大；而且 1.3 以上没逐页检查过 |
| 最小档保留 1.0，五档 1.0–1.3 每档 0.075 | Junyu 给的是 1.06 起；如果要保留 1.0，只改 `multiplier` 一个数 |
| 换档后弹出对话框问 | 会挡住刚变大的页面，老人看不到效果；框放在卡片里不挡东西 |

## 后果

- 对研究：只是显示大小，两组相同，不影响对等性和测量。默认字号由 1.0 变 1.06，算参与者能感受到的改动，记入 STUDY_CHANGELOG。
- 对开发：最大值没变，CI 本来就扫 1.3；五档的扫描结果见 history。
- 对论文：无。
