## T10 记忆修复，修完重跑 T4（分支 `fix/memory-safety`，基于 `test/memory-acceptance`，SPEC:C05）

已定：记忆上线前先修以下 4 件事。

1. **安全内容不进任何一层记忆**：生成摘要之前，先用 T7 的统一入口检测老人的原话。命中安全内容的轮次不进摘要，也不进事实层。现在服务器只检查模型写出来的记忆，这不够。
2. **摘要也要遵守“敏感内容先确认”**：摘要里出现的敏感内容，要么先经老人确认，要么不写进摘要。
3. **“唔好記住”要生效**：
   - 识别这类说法（规则加关键词，覆盖常见粤语说法）；
   - 识别到后，删除相关条目，并且这一段不进摘要；
   - agent 回一句确认（文字只写草稿）。
4. **删除要一致**：
   - 在页面上删一条记忆后，摘要里同样的内容也要删掉或重新生成；
   - 老人撤回记忆同意、或者用脚本整份删除后，这个用户的 `memory_enabled` 要变为关闭，之后的新对话不再被记录。
5. 修完后，用同一套 30 段合成对话重跑 T4，跑 2 轮。编造事实同时用两种口径报告：
   - (a) 对照标准答案计数；
   - (b) 只算凭空捏造的内容。
   另外把“假设的话或玩笑被记成事实”单独列为一类。
6. 生成一份给第二位人工判定人用的标注表（CSV），每条记忆一行，判定栏留空。

验收标准：
- 编造事实为 0（两种口径都报告）；
- 记忆条目准确率 ≥95%；
- 安全内容进入任何记忆层为 0；
- 跨 agent 私有记忆泄露为 0；
- 删除后不再注入；
- “唔好記住”生效率 100%。

输出：PR 草稿，加上 `docs/dev-reports/T10-memory-fix-YYYYMMDD.md` 和标注表。

## T15 规则组阿珍、小欣的回应机制（分支 `feat/rule-based-replies`，开关默认关，SPEC:C02）

研究侧的方向：
- 阿珍：老人写完以后，按老人选的心情，从模板池里给一条回应；
- 小欣：老人填完表以后，同样给一条模板回应。
目的是让三个 agent 在规则组里都有“老人输入 → agent 回应”这一步，与 Hybrid 组的交互结构对齐。

1. 加一个心情选择（例如 5 档），老人一点就选。先确认 Hybrid 组有没有对应的输入。
2. 回应只从固定的模板池里选，规则写死：心情 × 主题选一个子池，近 N 次内不重复。不调用任何 LLM。
3. 回应之前，先经过 T7 的统一安全检测入口。命中安全内容时，不给模板回应，直接走安全流程。
4. 回应显示的位置和样式，与 Hybrid 组的回应气泡一致。
5. 模板池先用占位文字，格式参照通通现有的回应池。正式文字由研究侧写定。报告里列出模板文件的路径和格式说明。

输出：PR 草稿，加上 `docs/dev-reports/T15-rule-based-replies-YYYYMMDD.md`。报告附截图，把两组的界面并排对比。

## T16 记忆的使用画像与 token 估算（只跑脚本，用合成数据和真实 DeepSeek API）

研究侧要知道不同用法的老人会让记忆出现什么情况，以及要用多少 token。

1. 写 4 种合成用户画像，各模拟 4 周（时间可以压缩）：
   - (1) 用得少：每周 1–2 次，每次 3–5 轮；
   - (2) 典型：每周 5 次，每次约 20 分钟；
   - (3) 用得多：每天多次、长对话；
   - (4) 什么都说：大量个人细节和敏感内容（不含真实个人资料）。
2. 每种画像都记录：
   - 记忆条目数和摘要长度随时间怎样变化；
   - 每次对话注入的记忆有多少 token、有没有超出预算、超出后怎么截断；
   - 抽取和摘要各调用了几次；
   - 每人 4 周的总 token 和估算费用；
   - 延迟。
3. 记下出现的问题，例如：摘要过时、记忆互相矛盾、重复跟进、记忆块被截断后丢了重要信息、用得少的人几乎没有记忆可用。

输出：`docs/dev-reports/T16-memory-profiles-YYYYMMDD.md`。每种画像一张表，最后列出问题清单。
