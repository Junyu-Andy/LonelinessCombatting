# 功能核对结果 2026-10-06（C01–C22）

- 核对对象：`main` 分支提交 `27113ca`，登记表 `docs/spec/feature-registry.md`。
- 方式：只读代码和配置，没有改代码，没有连生产 Firestore。
- 本环境没有 DeepSeek 密钥，所有需要真实调用模型才能判断的地方都标了“无法判断（本环境无法调用 DeepSeek）”。
- 没做核对 prompt 里的“第二步”（加 `// SPEC:Cxx` 注释），等研究侧确认。
- 标记说明：H = Hybrid 组（A 组），R = Rule-based 组（B 组）。“（推断）”= 从代码推出来的，没有实际运行验证。

## 摘要

1. **不一致**：C01（客户端能自己写分组）、C02-R（小欣、阿珍在规则组没有回应池，是表单）、C04（只有聊天轮次记 `model`，记忆抽取等不记）、C12（词库是 v5 不是 v4；5-flag 不是安全标记；行动计划 B、思维练习没有安全检测）、C14（1–7 分点选，不是 0–100 滑杆；两组弹出条件不同）、C15（UCLA 不在 app 内；孤独探针关闭）、C18（语音输入已上线，没有开关）、C19（后台显示分组人数，没有安全事件和问卷完成情况，权限规则也不支持）、C20（没有整人删除）、C22（Phase A 用记忆 v0，没有每日 Brief PR 推送，没有第 7 日最后问卷）。
2. **缺失**：C13（代码里没有任何 LoRA 接入）；C15 里的 app 内 UCLA。
3. **无法判断**：C21（仓库里没有 F2–F5 的定义）；C15 里的 ADA（代码里没有叫 ADA 的问卷）。
4. **一致**：C03、C06、C07、C08、C09、C17。
5. **待定/待确认，只报现状**：C05、C10、C11-R、C16，以及 C13-R。
6. 测试：Functions 和规则测试全部通过；Flutter 四套构建变体全部通过（见“测试运行结果”）。

## 登记表之外的组间差异

先说结论：组间差异基本都在“回应由谁生成”这条线上，但有几处超出登记表写明的范围，尤其是**安全检测覆盖**和 **Brief PR 弹出条件**。

**界面**
- 首页选完心情后，只有 H 组弹出“想同小欣講多兩句”提示，进入小欣签到 A（`lib/features/today/presentation/widgets/greeting_hero.dart:119–131`）。

- Brief PR 弹出条件不同：H 组签到要 ≥2 轮，R 组签到和怀旧一次提交就弹（C14）。这会让两组 Brief PR 的数量和时机不同（推断）。
