# 0027：第 2 周 DJG 在 App 内做全部 6 题，分数由服务器算，只在 Phase B（开关默认关）

- 日期：2026-10-07
- 状态：提议中（随 T18 的 PR 草稿，合并即采纳）
- 影响范围：phase_b × 两组（Phase A 和 pilot 不变）
- 相关代码：分支 `feat/djg-w2`（`functions/djg_w2.js`、`functions/index.js` `djgW2Dispatch` / `onDjgResponseWritten` / `week2Push`、`firestore.rules`、`lib/features/assessment/data/djg_w2.dart`、`lib/features/assessment/presentation/pages/djg_w2_page.dart`、`lib/core/scheduling/pending_prompts_service.dart`）

## 背景

研究侧 10/7 定了：第 2 周（W2）的 DJG 只在 App 内做，不再面谈，做全部 6 题（情感 3 + 社交 3，H2' 要用社交分量表）。题目和选项按已批问卷包 §3 照抄。

App 里原来就有一份 DJG：第 14–16 天一次，`timepoint: "week2"`，存在 `users/{uid}/djg_es`（T14 报告 2.4）。它就是 W2，但题目是粤语草稿，选项是「係 / 多少啦 / 唔係」，只能整份跳过，只存总分，错过了不记缺失，也没有提醒。

## 决定

1. **替换现有 W2**：开关打开后，Phase B 构建不再显示旧的 `djg_es` 问卷，改显示新的 6 题版。旧集合 `djg_es` 和旧数据不删，旧页面代码保留给 Phase A 构建（Phase A 行为不变）。
2. **题目和选项**：照抄问卷包 §3（6 题，选项「是 / 大致是 / 不是」）。一屏一题，可以返回上一题，可以跳过单题（记为 `skipped`）。每答一题就保存一次。两组同一个页面，代码里不看分组。
3. **时间**：W0 入组日算第 1 天（沿用现有「入组第 N 天」的算法）。第 14 天香港时间 10:00 推送一次，首页出现问卷卡；窗口第 14–20 天；推送 24 小时后还没提交就提醒一次；窗口过了还没提交，服务器记为缺失（`status: "missed"`），不再推送。天数、窗口长度、推送钟点、提醒间隔都可以在配置里改。
4. **W0 日期**：暂时用账号创建时间 `createdAt`。客户端和服务器各有一个函数负责「取 W0 日期」（`lib/core/scheduling/w0_date.dart`、`functions/djg_w2.js` `w0DateKey`），T19 由研究员登记 W0 后只改这两个函数。
5. **存储**：独立集合 `users/{uid}/djg_responses/W2`。客户端只能写原始答案、状态（作答中 / 已提交）和时间；**分数、是否超出窗口、推送时间、缺失标记只能由服务器写**。已提交或已记缺失之后，客户端不能再改。分数由服务器在提交后计算（`onDjgResponseWritten`）：有题跳过时，对应分量表和总分记为空（缺失），不按 0 分算。
6. **研究编号不写进这份文档**：决策 0021 规定研究编号不能让 App 看到。导出时由盲法导出按行加上研究编号。
7. **推送**：复用现有推送方式（服务器定时函数，按 `fcm_tokens` 推到本人手机，写 `events` 记录）。两组内容和时间完全相同。推送文字现在是占位，**带【占位】字样时服务器不发**，只记日志；研究侧定稿后替换。旧的 `week2Push` 对开关打开时的 Phase B 参与者不再推，免得同一天推两次。
8. **盲法导出**：`djg_responses` 加进 v2 导出的白名单（原始答案、分数、状态、时间），不带任何能看出组别的字段；检查脚本同步更新。
9. **开关**：`app_config/phase_b.djgW2InAppEnabled`，默认关（文档不存在 = 关）。客户端还要求是 Phase B 构建（`PHASE_B=true`）；服务器只处理 Phase B 参与者（`cohort == "phase_b"`，没有 cohort 时看 `armAssignmentMode == "randomise"`）。T21 会改成按参与者的研究期字段。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 在旧的 `djg_es` 集合里直接改 | 新旧版本题目、选项、计分都不同，混在一个集合里分析容易出错；旧数据要原样保留 |
| 客户端算分、存分 | 客户端可以改分数；分数是结局指标，保守做法是服务器算 |
| 客户端算分，规则检查分数和答案是否一致 | 规则写起来很长、容易错，计分规则改了还要同时改规则 |
| 缺失记录由客户端在打开首页时写（像 Weekly PR） | 老人整个窗口都没打开 App 时就永远没有缺失记录 |
| 占位推送文字也照发 | 老人会看到「占位」字样；宁可不推 |
| 研究编号存进文档 | 违反决策 0021（App 看得到研究编号） |

## 后果

- 对研究：W2 的 DJG 改为 App 内自填，6 题。主要结局（情感分量表 0–3）和社交分量表分开存。第 2 周的 ADA 仍按原样出现（T17 会在 Phase B 隐藏）。protocol / DMP 里 W2 的施测方式要写成「App 内自填」。
- 对开发：新集合、新规则、两个服务器函数、一个新页面。T19 换 W0 来源时只改两个函数；T21 换研究期判断时改开关判断。
- 对论文：方法部分写 W2 为 App 内自填，跳题时分量表记缺失；局限部分可提 W0/W4/W8 为纸本或电话、W2 为 App，施测方式不同。
