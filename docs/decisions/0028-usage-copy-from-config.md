# 0028：提到使用频率的文字改为从 `app_config/usage_copy` 读取，没有定稿时显示原文

- 日期：2026-10-07
- 状态：提议中（PR 草稿，未合并）
- 影响范围：所有 cohort × 两组（相同）
- 相关代码：分支 `chore/usage-copy`（T20）

## 背景

研究侧 10/7 定了：建议每天用，每周至少 5 次，不强制。最终措辞要等 ICF 定稿后才给。App 里已经有几处文字在讲"多久用一次"（例如小欣"日日陪你傾偈"、人生點滴"每星期一節"），写死在代码里，改一次就要发一个新版本。

## 决定

- 这些文字改为先读 Firestore 文档 `app_config/usage_copy`，一个位置一个键（中文 `_zh`、英文 `_en`）。
- 文档不存在、读不到、字段为空、或内容还带【占位】时，显示现在的原文。所以合并上线后老人看到的和现在完全一样。
- 两组读同一份文档，代码里没有按组别的判断。
- 只放现有的位置，不新增"建议每天用"的说明，也不新增"没用够次数"的提醒。
- prompt 和规则组模板里提到频率的地方不在这次改（改 prompt 要 PI 审核、要新版本文件），只在 T20 报告里列出。
- 规则：登录用户可读，客户端不能写（沿用 `app_config/*` 已有规则）。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 直接把新措辞写进代码 | 措辞还没定稿；而且以后每改一次都要发版本 |
| 用一个键放一整段"使用建议"，新加一处显示 | 任务单只要求改读取方式，不上线新措辞；新加显示位置等研究侧决定 |
| 放进 `app_config/phase_a` | 那份是 Phase A 的运行参数，T21 正在把它按研究期拆开；文案单独一份更清楚 |

## 后果

- 对研究：写入定稿文字后，老人重开 App 就看到新文字，不用发新版本。每次写入都要在 `docs/STUDY_CHANGELOG.md` 记一行（谁、何时、哪个键、影响的 cohort）。两组文字永远相同。
- 对开发：新增 `lib/core/config/usage_copy.dart`（解析，纯 Dart）和 `usage_copy_loader.dart`（启动时读一次，3 秒超时）；7 个位置改为经它取字。
- 对论文：干预材料描述里，使用建议的措辞以 changelog 记录的生效日期为准。
