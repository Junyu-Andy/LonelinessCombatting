# NNNN：回忆改成两组同一份开放问题稿，差别只在每题之后的回应；每周整理成小篇章，评三题，可改；离开按钮改名

- 日期：2026-10-20
- 状态：提议中（开发窗口草稿，App 部分；服务器部分另有分支。等 Junyu 定编号和下面“要 Junyu 定”的几点）
- 影响范围：pilot、run-in（PB-）、rct（RCT-）× 两组
- 相关代码：分支 `claude/zealous-fermat-8rgqtg-reminiscence-app`（1020d 第二至第八节的 App 部分；接 `claude/zealous-fermat-8rgqtg-keyboard`）

## 背景

10/19 产品窗口定（1020d，decisions-log 第 41 至 44 条）：回忆两组用同一段开场、同样 8 题、同样的输入框和「唔想講」，题目一路顺序问；两组唯一的差别在老人答完一题之后：Hybrid 组模型追问一条再回一句，规则组出固定句。每周答完整理成一篇小文章（小篇章），两组同一个画面，评三题，可以改。旧回忆页两组差别很大（Hybrid 组自由聊天，规则组一个大输入框），组间可比性差。新行为放在开关后面，默认关。

## 决定

1. **一个页面，两组共用**：新页面 `ReminiscenceV2Page`。所有进回忆周的入口（回忆首页、我嘅故事的本周入口和时间线）经 `ReminiscenceRouter`，开关 `reminiscenceV2Enabled` 开时打开它；关时打开旧页面，一字不变。
2. **同一份文字**：开场、32 题、固定句、结束句、按钮、规则组小标题、评分三题都在 `docs/spec/copy/reminiscence-v2.md`，代码 `reminiscence_v2_copy.dart` 两组读同一份，测试逐字比对。全部是草稿。
3. **每题之后**：规则组出固定句（一般句三句轮换、近 2 次不重复；第 7 题后出第 7 题那句；第 8 题后直接出结束句），**零 LLM 调用**；Hybrid 组模型追问一条（`[回憶·追問]`），老人答后模型回一句（`[回憶·回應]`），然后出下一题，提示词 key `ah_jan_ah_bak_v3`、moduleId 仍是 `m3_reminiscence_w{N}`。追问上限默认 1，`app_config/phase_b.reminiscenceFollowupsMax` 可改 2。两组撳「唔想講」都出「冇問題，我哋講下一樣。」，不调 LLM。模型失败时出一般句，记一条 `reminiscence_v2_llm_fallback`。
4. **对话保留**：每周一份 `users/{uid}/reminiscence_v2/week_{N}`，每说一句就存。再进来显示全部对话，从没答的那题（或没答的追问）接着。保留对话的同意关着时，服务器那份只存进度、不存原话，原话只留在手机里。
5. **小篇章**：撳「完成今個禮拜」。规则组在手机上即时排版（每题小标题加老人原话，「唔想講」的题不出现），不推送；Hybrid 组写一份请求到 `users/{uid}/reminiscence_chapters/week_{N}`，服务器生成后推送，App 看到 `ready` 就显示「第 N 章整理好喇」。两组同一个画面：标题、正文、三题评分（一次一题，1 至 7，可「唔評住」）、「改一改」「儲存」。存原稿、改稿和改动比例。原来的 80 字小结照旧生成和保存。回忆首页的「我嘅回憶」换成「我嘅人生小篇章」。
6. **安全**：每句老人输入照常过同一个安全检测（输入点 `chat_reminiscence`，两组相同）。命中 acute 或 `moderate_interrupt` 时，这次不再出题，走现有安全流程，那句不进小篇章；下次进来从下一题接着。命中 `moderate_review`（亲人离世、过去的困难）照常继续：Hybrid 组模型照提示词规矩回应，规则组第 1 至 6 题用 Z5 一组哀伤模板（rule-templates.md 第 3 条），第 7 题仍用第 7 题那句。
7. **有效会话**：两组同一标准，这次进入期间答了至少 3 题（追问的回答、「唔想講」不算），`app_config/phase_b.reminiscenceV2ValidMinQuestions` 可改。Brief PR 邀请规则不变。
8. **离开按钮**（开关 `leaveButtonV2Enabled`）：回忆页左上角「離開（會暫存）」；其他陪伴者聊天页的「今日傾到呢度」改「離開」，首次说明改新句子，每台手机另记一次（看过旧说明的人也会看到一次新说明）。按了只是离开，会话结束规则和 Brief PR 不变。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 在旧的 Hybrid 页、规则组页里各自加分支 | 两组题目来自两处代码，容易不一致；开关关时旧行为难保证不变 |
| 命中 `moderate_review` 也停止出题 | 回忆题本身会引出离世、难捱的事（第 7 题、第 3 周第 5 题），一停就做不完；现有安全流程对 `moderate_review` 本来就是只记录、不打断 |
| 规则组哀伤内容也出一般句（例如「聽落好有畫面」） | 对离世内容不合适；沿用 rule-templates.md 第 3 条的 Z5 |
| 第 8 题后规则组也出一般句 | 「我哋講下一樣」后面接「問題問完喇」自相矛盾；结束句本身有「多謝你」 |
| 小篇章评分放进 Brief PR 或单独一页 | 1020d 第七节要求在小篇章下面、改一改之前，不进 Brief PR |
| 对话只存服务器，同意关时不存 | 关同意的老人中途离开就要从头再答；改为存手机 |

## 后果

- 对研究：回忆两组问同样的题，差别只在每题之后的回应和小篇章的写法（Hybrid 组模型写，规则组原话排版）。新数据：`reminiscence_v2`（逐句对话、进度）、`reminiscence_chapters`（请求、原稿、改稿、改动比例）、`reminiscence_chapter_ratings`（三题评分、研究周）、`sessions.reminiscenceQuestionsAnswered`。登记表回忆一行、B07 §5、B12/B13 的评分条目要改（1020d 第十节，产品窗口）。有效会话定义改为“答了至少 3 题”，要写进分析计划。
- 对开发：App 新文件见报告；共用代码只加了会话规则一项、两个开关、Phase B 配置两项、Brief PR 1–7 量表改为公开组件、离开按钮的文字。服务器部分（小篇章 Cloud Function、`ah_jan_ah_bak.v3` 提示词、推送、Firestore 规则）在另一个分支，两边按报告里的约定拼接；开开关前要先部署 Functions 和规则。
- 对论文：方法部分写回忆两组同一份开放问题、Hybrid 组每题一条追问加一句回应、规则组固定句；小篇章生成和评分；有效会话定义。局限：小篇章评分是探索性结局。
