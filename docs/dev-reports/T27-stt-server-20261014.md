## 4. 流程

**App**（`lib/core/voice/voice_input_button.dart`）

1. 开关关：按钮不渲染，不创建录音器，不申请权限（和以前一样，`test/phase_b_flags_test.dart`「voice button renders nothing while voice input is off」不变）。
2. 开关开，按一下：申请麦克风权限（没给 → SnackBar 提示，结束）；用 `record` 包的流模式录 16 kHz 单声道 PCM，一段段追加到内存里的 `BytesBuilder`。**不写文件**（`voice_recorder.dart`）。
3. 再按一下（或满 60 秒自动停）：停录，把 PCM 包成 WAV（`wav_encoder.dart`，纯 Dart，44 字节头），base64 后调用 `transcribeAudio`（`asia-east2`，App 端最长等 75 秒）。
4. 成功：文字接在已打的字后面填进输入框。**不自动发送**；老人按发送时和打字完全一样，经同一条 `_send` 路径（词库、分类器、危机流程）。`test/phase_b_flags_test.dart`「voice on: a dictated distress sentence keeps the safety flow and never reaches the LLM」证明：口述一句急性安全词 → 输入框里有这句 → 按发送 → LLM 调用 0 次，显示急性安全回应。
5. 失败：S6 小卡 + `voice_transcription_failed` 事件；输入框不动；麦克风立刻可以再用。
6. 发送前（B03 `stopForSend`）：正在录音就作废录音，不上传；正在转写就丢掉结果，不写回已清空的输入框。

**服务器**（`functions/index.js` `transcribeAudio` → `functions/stt.js`）

1. 登录检查 → 开关检查（`assertFeatureEnabled`）→ `audioBase64` 非空 → ≤ 10 MB（超过返回 `too_long`，不调 Google）。
2. 调 Google 一次，每次最长 30 秒。失败类别是 `timeout`（gRPC 4）、`unavailable`（14、8）、`server_error`（其他）时**重试 1 次**；`no_speech`（Google 返回空文字）、`too_long`（Google 的 INVALID_ARGUMENT 说时长超限）不重试，因为同一段音频再试结果一样。最多两次尝试，`stt_test.js` 证明不会有第三次。
3. 返回 `{transcript, confidence, model, region, latencyMs, attempts}`；失败抛 `HttpsError`，`details = {category, attempts}`。App 优先读 `details.category`，读不到按错误码映射（`transcription_repository.dart`）。
4. 日志：只有一行 `console.warn("stt failed", {category, attempts, grpcCode})`。**不打印错误信息原文、不打印音频、不打印文字**；`stt.js` 整个文件没有 `console.*`。`stt_test.js` 扫描这两处。

## 9. 决策记录草稿（编号待开发窗口分配）

**标题**：语音改走研究服务器的 Google STT v2：实现层面的几个决定

- 日期：2026-10-14
- 状态：草稿
- 影响范围：phase_b、pilot × 两组（相同）；开关 `voiceInputEnabled` 打开后生效
- 相关代码：`lib/core/voice/`、`functions/stt.js`、`functions/index.js`

**背景**：研究侧已定（登记表 C18，10/9 第 13 条，10/10 第 2 条）：录音经研究服务器送 Google STT v2，只用 asia-southeast1，重试 1 次，失败显示 S6，记失败事件，不开数据记录。决策 0019 定了开关。本记录只写研究侧没写到的实现选择。

**决定**：
1. 录音格式 16 kHz、单声道、16 位 PCM，App 包成 WAV，服务器用 `autoDecodingConfig`。理由：语音识别的标准采样率；60 秒只有 1.9 MB，远低于同步接口 10 MB 上限；WAV 头 44 字节纯 Dart 就能写，不用再加编码库。
2. 录音用 `record` 包的流模式进内存，不用文件模式。理由：任务要求不落盘；流模式本来就不写文件，不用“写了再删”。
3. 只重试 `timeout`、`server_error`、`unavailable`；`no_speech`、`too_long` 不重试。理由：后两种是音频本身的问题，再送一次结果一样，只会多等。
4. S6 由按钮自己贴在麦克风上方（`OverlayPortal`），不要求每个页面布局。理由：13 个页面有麦克风，各自加提示容易漏、容易不一致；贴在按钮上两组、所有页面天然一样，仍在输入框那一行，不是聊天气泡。
5. 单次语音 60 秒自动停。理由：Google 同步识别上限 60 秒；超过要换异步接口，另算。
6. 服务器错误只记类别和 gRPC 代码，不记错误原文。理由：错误原文有可能带回请求字段。
7. 语言写死 `yue-Hant-HK`，客户端不能改。理由：少一个要审的参数；App 本来只服务粤语老人。

**考虑过的其他方案**：
| 方案 | 为什么没选 |
|---|---|
| 保留手机系统识别作后备 | 研究侧明确不要（声音会去厂商云端，不受控） |
| 服务器先存到 Cloud Storage 再识别 | 多一处存音频，违反 C18 |
| S6 用 SnackBar | 从屏幕底部弹出，和输入框不在一起，老人容易错过；也和“在输入框旁”不符 |
| 每个页面各放一个 S6 文本 | 改 13 个页面，容易不一致 |
| 失败一律重试 | `no_speech` 重试没有意义，老人多等 30 秒 |

**后果**：对研究：转写失败率可以从 `events` 的 `voice_transcription_failed` 按类别统计，两组可比。对开发：以后要换模型或区域只改 `functions/stt.js` 的常量，测试会要求同步改。对论文：Methods 写明“语音经研究服务器由 Google Cloud Speech-to-Text v2（chirp_2，新加坡区域）转写，未启用数据记录，录音不保存”。

## 12. 架构优化观察（不在本任务改）

1. **13 个页面各自拼输入行**：每个页面自己摆 `VoiceInputButton` + `TextField` + 发送键。这次 S6 只能靠按钮自己贴卡解决；以后再有“输入框旁的提示”（例如离线、字数）还是会重复。建议抽一个共用的 `Composer` 组件，两组一起用。
2. **`functions/index.js` 太大**（2000+ 行，ESLint 有 1200 多条既有的缩进告警，CI 不跑 lint）。本任务把 STT 放到 `stt.js` 并对新文件 lint 干净；建议逐步把其他 callable 也拆出去，并把 `npm run lint` 加进 CI（先只对新文件）。
3. **事件名散落**：`PhaseAEvents` 列了大部分事件名，但 `voice_issue`（旧）、`voice_transcription_failed`（新）等在各自文件里。建议集中到一个事件名清单，和 `docs/dev-reports/T2-data-dictionary` 对表。
4. **`AnalyticsService` 对 uid 为空的事件只缓存不落库**：失败事件在未登录状态会丢（现在登记门保证了有 uid，影响小）。
5. **`FakeAsync` 下 `StreamSubscription.cancel()` 的坑**：已关闭的流的 `cancel()` 返回根 zone 的已完成 future，`await` 它会在 widget 测试里卡死。本任务改为不 await；别处若有同样写法要留意。
6. **`record` 固定在 6.x**：7.x 要求更新的 Flutter（Flutter 3.35.3 受 Gradle 8.12 限制）。升级 Flutter 时一起升。

## 13. 要带回研究侧的发现

1. **HREC 对 STT 修订的批准还没到**：代码已就位，开关 `voiceInputEnabled` 保持关。批准到了再开，开的那天在 changelog 补一行。
2. **声音离开手机，但去向受控**：现在是 手机 → 研究服务器（asia-east2，香港）→ Google Speech-to-Text（asia-southeast1，新加坡），不存音频、不开数据记录。ICF / protocol 里关于语音的描述要和这条路径一致（原来“手机系统识别，可能到厂商云端”的说法要改）。
3. **手机键盘自带的语音输入**（Gboard 麦克风、iPhone 听写）不经过 App，App 关不掉（决策 0019 已提）。开关关着时老人仍可能用键盘听写，那条路径不受我们控制。
4. **失败率可以按类别统计**：`events.voice_transcription_failed.category`，两组相同。试跑期间看一眼 `no_speech` 和 `timeout` 的比例，决定要不要调 60 秒上限或提示文字。
5. **英文 S6 没有定稿**，只影响测试员。
6. **Google 控制台的 data logging 要在开关打开前再核对一次并截图**（第 6 节）。
