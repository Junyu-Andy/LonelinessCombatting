- 状态：已被 0072 取代（10/21）
- 影响范围：不影响参与者。所有 cohort × 两组：App、Functions、Firestore 规则都不改，老人看到的完全一样。只多了一个研究员在自己电脑上用的工具
- 相关代码：分支 `claude/zealous-fermat-8rgqtg-dashboard`；`tool/dashboard/`

## 背景

App 里的研究员后台慢，手机上难用。Junyu 要在电脑上看运营数据（10/20 第 61 条），并把「確認處理」和「誤觸」也挪到电脑上（10/20 第 62 条 (1)）。具体做法见 10/20 第 65 条和 `dev-tasks` 1020i 第二版第二节。冻结后只允许不改干预的工具（10/19 第 33 条）。

## 决定

1. **做法**：用 Node 写一个本机网页，放在 `tool/dashboard/`，只在 `127.0.0.1` 打开，不部署到网上。研究日、问卷窗口、跟进阶段、有效会话这些规则，直接调用服务器 `functions/` 里的同一份代码（`study_week`、`weekly_schedule`、`ops_dashboard` 的纯函数、`daily_checkin_push.rowCompletes`），所以算出来和 App 研究员后台一致。
2. **读数据**：
   - 用一个只给看板用的服务账号，角色 `roles/datastore.viewer`。不用 Junyu 现有的那把钥匙。
   - 看板启动时问 Google 这把钥匙有哪些权限（`testIamPermissions`，本身不读不写数据）。能写 Firestore 就拒绝启动；不能读也拒绝。
   - 代码里有一张白名单：只许读列出来的集合，每次读都只取列出来的字段（Firestore 字段投影），所以答案、心情值、对话这些字段根本不会传到电脑上。
   - 序列、`randomization_state`、`sequence_versions` 和分配日志写死不读，有测试守住。
3. **结局数据**：
   - 结局问卷只读「完成与否」需要的字段（`status`、`answeredAt` 等），不读答案。
   - 每个返回给网页的结果都先过一道检查：发现答案类字段名就整页报错，不显示。
   - 总览页的「每周问卷」一格只看 Weekly PR（过程数据），和 App 运营看板相同。结局问卷完成情况只出现在两处：「今天要做」的问卷名单（不带组别），和全体合并的完成率页（Phase B，少于 5 人不显示）。这样任何页面都不会把结局和组别放在一起。
   - 每日心情只显示哪天记了，不显示心情值。
4. **写入**：
   - 看板的服务账号只读，看板程序本身不写 Firestore。
   - 「確認處理」和「標記誤觸」由 Junyu 在网页上用自己的 App 账号登录（电邮和密码，和 App 一样），浏览器直接调用现有服务器入口 `acknowledgeAlert`、`markSafetyFalseAlarm`。服务器照旧检查 `unblinded` 角色、照旧写 `alert_audit_log`。
   - 登录凭证只放在网页内存里，不存盘，也不经过看板程序；关掉网页就登出。
   - 两个按钮分开，并提示「标误触不等于确认」。
5. **对话**：对话原文不进看板。App 现在也没有「查看对话」（见 1020i 第 2.5 节 (3) 的回答）；要做另写决策记录。
6. **算不算改干预**：不算。App、Functions、规则一行不改，参与者那边的效果和在 App 后台按按钮完全一样。它也不再是 10/19 第 33 条说的「只读脚本」：看板会经服务器写告警、安全事件、check-in 和审计日志。所以用这份记录说明；不进 `STUDY_CHANGELOG`，不算偏离。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| Python + Streamlit | 研究日、问卷窗口等规则要用 Python 重写一遍，可能和 App 对不上；登录、调用服务器入口也要手写 |
| 直接调用服务器的 `loadPerson` / `people` | 它们会写 `ops_daily`（只读账号会报错），而且读整份文档，包括 `enrollments` 里的 W0 基线分、序列位置，和安全事件命中的词 |
| 看板用服务账号直接写告警 | 绕过服务器的角色检查和审计日志；10/20 第 62 条要求走同一入口 |
| 读数据也全部走 Junyu 登录，服务器加只读入口 | 电脑上不用放钥匙，但要改 Functions、冻结后部署；以后可以再考虑 |
| 总览页每周问卷显示整份（含 DJG-ES、PGIC、S12） | 和组别放在同一行，等于能按组数结局完成情况，违反 2.3(1) |
