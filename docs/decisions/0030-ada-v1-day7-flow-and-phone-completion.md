## 背景

研究侧 10/7 给了 ADA 定稿规格 `docs/spec/instruments/ada.md` v1.0。和 T17（0026）的占位版不同的地方：题目措辞照用粤语原文；A 部分固定"過去 7 日"、选项按次数；第 1 次到访短版是 B + D（不含 A）；第 7 日在家自己做，要有提醒、进度、中途保存、求助电话、电话补做和研究员页面。ada.md 还要求记录"研究编号"，但决策 0021 规定 App 读不到研究编号、编号不写进 `users/{uid}`。

## 决定

1. **题目照抄 ada.md 第 3 节**（`lib/features/ada/data/ada_items.dart`），新版本号 `ada-v1.0-20261007`。旧的占位数据（`ada-placeholder-20261007`）不动，靠版本号区分。陪伴者名字旁边放现有头像（`assets/agents/*_avatar.png`），阿珍/阿伯按配对性别；没有配对时两名并列、不猜头像。
2. **表单**：短版 = B + D，全版 = A + B + C + D。默认 `visit1` 第 1 天短版、`day7` 第 7–9 天全版，仍从 `app_config/phaseA_schedule` 读。回忆窗口不再可配（题干固定"過去 7 日"）。
3. **第 1 次到访最后加一屏选第 7 日提醒时间**（选项和默认时间都在配置里；整点、08:00–21:00）。存在 visit1 文档的 `day7ReminderTime`；不选记 `skipped`，服务器用默认时间。
4. **第 7 日流程**（`day7_flow_page.dart`）：开头说明一共几部分、预计时间（没配置就显示【占位】），然后第 1 部分 ADA 全版、第 2 部分开放题，每部分顶上"第 N 部分，共 M 部分"。每部分各自一份文档、每屏保存；下次打开从第一个没交的部分、停下的那一屏继续。首页原来 ADA 第 7 日和开放题两张卡合成一张"第 7 日問卷"。
5. **提醒**：新的定时函数 `adaDay7Dispatch`（每小时，香港 08:00–21:00）。窗口第一天起，到老人选的整点推一次；24 小时后还没做完再推一次；过了最后一天（默认第 9 天）记"已超时"。只推 Phase A 参与者，不推测试账号。推送文字带【占位】时一条都不发（同 T18）。
6. **求助**：每一屏顶上"唔識填？打俾研究員"。号码读 `adaHelpPhone`。**没配置号码时不拨号**，弹一句"可以先撳「跳過」，研究員之後會打電話俾你"（草稿）。
7. **电话补做**：研究员页面（`ada_staff_page.dart`，从研究员后台进入）列出每个 Phase A 参与者第 7 日的情况：未开始 / 进行中 / 已完成 / 已超时（超时的标"做咗一部分"）。没完成的可以点"電話代填"，用同样的页面代填，经 Cloud Function `adaStaffSave` 写入：服务器盖上 `channel: "phone_by_staff"` 和研究员 uid，已提交的不能再改。App 自己写的永远是 `channel: "app"`（规则检查），研究员开始代填后老人那边不能再改那份文档。
8. **安全**：老人自己填，照旧在 App 里经 `SafetyService`（`ada_free_text`、`day7_open_ended`）。研究员代填的文字由服务器用同一份词库（`functions/safety_lexicon.js`）检查，命中就写 `safety_events`（`source: form`，带 `channel: phone_by_staff`），之后去重、acute 通知 PI 都走原来的 `onSafetyEventCreated`。研究员屏幕上提示按安全流程跟进；老人的危机页不在研究员手机上弹。
9. **研究编号**：不写进答案文档。服务器在 `ada_status/{uid}`（客户端谁都不能读写）记 `researchId`，从 `research_id_map` 抄过来，只读不新建；没有编号时为空，之后每次更新再查。研究员页面只给非盲角色（`role: unblinded`，决策 0029）显示编号。
10. **权限**：研究员页面和三个 callable 都要 `role: blinded` 或 `unblinded`（决策 0029 的新角色；旧的 `researcher`、`pi` 不再有权限）。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 服务器把研究编号直接写进 `ada_responses` 文档 | 老人能读自己的文档，等于 App 能看到编号，违反 0021。放在服务器专用的 `ada_status`，分析时按 uid 对上 |
| 触发器顺便给没有编号的人生成编号 | 编号由分组（T12）或研究员登记（T19）发放；这里新建会多一条发号路径 |
| 研究员直接写 Firestore（规则放开给研究员角色） | 要放开所有参与者子集合的读写，范围太大；callable 只开放第 7 日两份文档，服务器统一盖渠道标记 |
| 没配置号码时隐藏求助按钮 | ada.md 要求每屏都有；隐藏后老人不知道可以求助。保留按钮、不拨号 |
| 提醒时间让老人自由选几点几分 | 推送函数每小时整点跑；自由时间会被推迟到下一个整点。给几个整点选项更清楚 |
| 研究员代填时在研究员手机上跑 App 的安全流程 | App 写安全事件要求 uid 是自己，研究员手机写不了老人的事件；危机页也是给老人看的 |

## 后果

- 对研究：ADA 有了定稿措辞和版本号，旧占位数据另算。第 7 日提醒推送文字、求助弹窗、提醒时间页、流程说明等老人看得到的文字都是草稿；预计时间等试跑。电话补做的记录带 `phone_by_staff`，分析时可以分开。
- 对开发：`functions/ada.js`（新）、`functions/index.js`（1 个定时函数、2 个触发器、3 个 callable）；规则加 `ada_status`、渠道检查；`tool/delete_participant.js` 加 `ada_status`。T19 换角色时要改 `functions/ada.js` 的 `STAFF_ROLES` 和研究员页面看编号的条件；T19 换 W0 时 `djg_w2.w0DateKey` 一处改，这里跟着变；T21 用研究期字段替换 `isPhaseAParticipant`。
- 对论文：Phase A 方法部分写 ADA 两次施测的版本和方式（第 7 日在家自填、可电话补做），以及电话补做的人数。
