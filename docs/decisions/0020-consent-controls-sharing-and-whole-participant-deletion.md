# 0020：三位陪伴者默认共享基本信息，不愿意的由研究团队后台关闭；设置页放回「保留對話紀錄」开关；新增整人删除脚本

- 日期：2026-10-07
- 状态：已采纳（负责人 2026-10-07 确认）；隐私页文案待负责人确认
- 影响范围：所有 cohort × Hybrid 组（共享只在 Hybrid 组有）；删除脚本两组都适用
- 相关代码：分支 `fix/privacy-consent`（T11，SPEC:C20）

## 背景

T2 报告发现三件事：
1. `consent.sharedContextUse` 存下来了，但没有任何代码读它。陪伴者之间照样共享记忆。
2. 「保留对话」同意写死为默认开启（同意页和陪伴者介绍页都写 `true`），要改只能改代码、重新发版。
3. 没有删除整个参与者的手段。`tool/delete_memory.js` 只删记忆。

难点：现有账号的 `sharedContextUse` 全是 `false`（同意页从来没写过这个字段）。如果直接让它生效，所有人的跨陪伴者共享会在部署当天一起关掉。

另外发现：设置页「保留對話紀錄」开关的组件写好了，但没放进页面，老人在 App 里关不掉。

## 决定

1. **共享同意统一打开**（负责人 2026-10-07）：三位陪伴者默认共享基本信息；不愿意的老人联系研究团队，由后台关闭。
   - 开关 `enforceSharedContextConsent`（Firestore `app_config/phase_a`）**默认开**。App 和服务器读同一个键；服务器上「没写 `false` 就算开」。
   - 新账号：同意页写 `sharedContextUse: true`（`sharedContextUseDefault` 默认 `true`）。
   - 现有账号：用迁移脚本 `tool/set_shared_context_consent.js --all` 统一改为 `true`。**必须先在正式项目跑迁移，再部署这个版本**，否则部署当天所有人的共享一起关掉。
   - 单独一个人不愿意：`tool/set_shared_context_consent.js --uid=<uid> --off`。脚本默认试运行，`--confirm` 才写，正式项目还要 `--production`。App 里没有让老人自己改的入口。
   - `sharedContextUse` 不是 `true` 的人：`sharedContextUse` 不是 `true` 的人，每个陪伴者只用自己的记忆：
     - 记忆 v1（服务器）：共享策略按 B 处理（各看各的），注入和抽取都一样；
     - 记忆 v0（App）：小欣签到不再引用阿珍/阿伯的回忆摘要；转介时不再把老人原话存进 `pendingReferrals.triggerSnippet`（存空字符串）。转介卡片本身照常出现。
   - 心情分数（`recentMoodSummary`，1–5 分）不算跨陪伴者记忆，不受影响。
2. **默认值改为配置**（同样在 `app_config/phase_a`，只影响还没点过同意页的新账号）：
   - `transcriptRetentionDefault`：默认 `true`（保持现状）；
   - `sharedContextUseDefault`：默认 `true`（见第 1 条）。
   - **只有同意页写 `sharedContextUse`**。App 只在登录时读一次资料，之后每次保存会把整份资料写回去；不这样改的话，手机上的旧值会盖掉迁移脚本或后台关闭的结果。
3. **整人删除脚本** `tool/delete_participant.js`：默认只列不删；`--confirm` 才删，删完再扫一遍，有残留就报错；输出只含数量的存证清单。周度盲法导出文件默认只数不改。
4. **已导出的盲法文件：保留不动**（负责人 2026-10-07 选定，T11 报告 4.4 的方案 2）。ICF 写明「已经用于分析的去识别数据不会删除」。**前提**：导出要先改成研究编号（T12）。在那之前导出里还是原始 uid，不能算去识别，ICF 的这句话要等 T12 合并后再写。删除脚本的 `--rewrite-exports` 保留，但不是默认做法，只在研究侧另有决定时使用。
5. **设置页放回「保留對話紀錄」开关**（负责人 2026-10-07），用原有组件和文字，两组都显示，默认开。关的时候全局开关和三个陪伴者各自的开关一起关（陪伴者介绍页给三位都单独写了 `true`，只关全局不生效）。
6. **隐私页改成简短、准确的版本**，细节交给同意书。文案等负责人确认。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 直接让 `sharedContextUse` 生效、不迁移 | 现有账号都是 `false`，部署当天所有人的共享一起关掉 |
| 共享同意默认关、让老人自己选 | 负责人选了默认开、不愿意的找研究团队，界面不加新问题 |
| 开关做成编译开关（`--dart-define`） | 要重新发版；而且服务器读不到 |
| App 和服务器各用一个开关 | 两个开关可能不一致；v1 用户同时走两条路径 |
| 删除时重写已导出的文件（方案 1） | 导出是全体参与者的研究数据；已经下载的副本删不到；改历史导出会让分析前后对不上。负责人选了保留（方案 2） |
| 在 App 里加「删除账号」按钮 | 老人看得到的新功能，要先定文案和流程；本批只做研究员用的脚本 |

## 后果

- 对研究：ICF 要写明「三位陪伴者默认共享基本信息，不愿意的可联系研究团队关闭」。迁移后现有 Hybrid 组参与者的共享和以前一样；被后台关闭的人，各陪伴者只用自己的记忆（要在 STUDY_CHANGELOG 记下生效日期）。老人现在可以在设置里关掉「保留對話紀錄」，ICF 的说法要对上。删除脚本让 ICF 的退出删除承诺有了执行手段，但 Cloud Logging、DeepSeek/Brave 那边、研究员本机导出、手机缓存仍删不到。
- 对开发：T10 之后改记忆时，`effectivePolicy`（`functions/memory.js`）要保留。T12 改导出（研究编号）后，删除脚本要加按研究编号找行、删对照表那一行。
- 对论文：fidelity 部分记录有多少人被后台关闭共享、多少人关掉了保留对话；局限部分写清哪些数据删不到。
