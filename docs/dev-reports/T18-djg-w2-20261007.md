# T18 第 2 周 DJG 改为 App 内全 6 题（SPEC:C15）

日期：2026-10-07。分支 `feat/djg-w2`。决策记录 0027。

## 结论

- App 里原有的 DJG **就是 W2**（第 14–16 天、`timepoint: "week2"`），所以按任务单替换。旧集合 `djg_es`、旧数据、旧页面都没删；Phase A 构建完全不变。
- 新版：6 题照抄问卷包 §3，选项「是 / 大致是 / 不是」，一屏一题、可返回、可跳题。存新集合 `users/{uid}/djg_responses/W2`。**分数由服务器算**，App 不能写也不能改。
- 时间：W0 起第 14 天 10:00 推送 + 首页卡片，窗口第 14–20 天，24 小时没交提醒一次，过窗口记缺失。全部可配置。
- **开关默认关**：`app_config/phase_b.djgW2InAppEnabled`。App 端还要求 Phase B 构建（`PHASE_B=true`）。
- **推送文字是占位，带【占位】时服务器不发**。老人看得到的其他文字也是草稿（第 5 节）。
- 两组同一个页面、同一条推送、同一个时间；没有任何 LLM 调用。
- 计分测试 11 种情况，预期分和实际分全部一致（第 4 节）。

  - 推送后满 24 小时（留 5 分钟余量，因为每小时整点跑）还没提交 → 提醒一次，写 `reminderSentAt`；

- **不重复推**：开关打开时，旧的 `week2Push` 跳过 Phase B 参与者（`functions/index.js:1804`），Phase A 参与者照旧。

## 4. 计分

服务器在提交后计算（`functions/djg_w2.js:71` `scoreAnswers`；触发器 `onDjgResponseWritten`，`functions/index.js:1874`）。原始答案照存，分数另存在 `scores`：

- 第 1–3 题：「是」「大致是」= 1，「不是」= 0 → 情感 0–3；
- 第 4–6 题（反向）：「不是」「大致是」= 1，「是」= 0 → 社交 0–3；
- 总分 = 两者相加（0–6）；
- 有题跳过 → 那个分量表为空（缺失），总分也为空。不按 0 分算。

## 要带回研究侧的发现

1. **任务单写现有 DJG 是 3 题，实际是 6 题**，而且就是 W2（第 14–16 天）。已按任务单替换；旧数据保留在 `djg_es`。如果已经有参与者答过旧版，那些数据的题目措辞和选项都和问卷包不同，分析时不能和新版直接合并。
2. **「第 14 天」怎么算**：现在 W0 当天算第 1 天，第 14 天是 W0 后 13 天（沿用 App 里现有的算法）。如果研究侧的意思是 W0 后满 14 天，把 `djgW2DayOffset` 改成 15 即可，不用改代码。
3. **W0 现在用账号创建时间**，T19 改为研究员登记的日期。登记前入组的人，两者可能差几天。
4. **窗口**改成第 14–20 天（旧版是第 14–16 天）。
5. **推送和页面文字要定稿**（第 5 节）。推送没定稿前服务器不会发，但首页卡片照样出现。
6. **缺失只在窗口结束后 7 天内补记**：开关晚开时，早已过了窗口的人不会被记缺失（他们本来就没有 App 内版本）。
7. 开关打开后，Phase B 仍会出现第 2 周的**陪伴者比较（ADA）**横幅（旧的「第 2 週問卷」卡片，只剩 ADA），和新卡片同名。T17 会在 Phase B 隐藏 ADA。
8. 测试账号不收推送（沿用 `week2Push` 的做法），但能看到首页卡片。
9. 「只在 Phase B」现在：App 看 `PHASE_B` 构建，服务器看 `cohort`（没有时看是否随机分组）。T21 改为按参与者研究期字段。
10. 打开开关那天要在 `docs/STUDY_CHANGELOG.md` 补生效日期；protocol / DMP 里 W2 的施测方式要写「App 内自填」。
