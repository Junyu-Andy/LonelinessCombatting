## T4 记忆模块验收测试（写测试，不改功能代码）

在分支 `test/memory-acceptance`（或独立 worktree）里做。

1. 写现状说明（一页）：
   - 读记忆模块的现有实现：v0 是 app 内滚动摘要，v1 是服务端摘要、事实和跟进；
   - 写清哪一版在当前 Phase B 构建里实际生效、开关在哪里、默认值是什么。
2. 写合成粤语测试对话，共 30 段。不要用任何真实参与者或试用者的对话。要覆盖：
   - 人物、地点、事件、计划；
   - 跟进日期，例如“下个礼拜四”“月尾”；
   - 敏感内容，例如健康、丧亲；
   - 安全场景，例如自伤、绝望的表达；
   - 前后矛盾的说法；
   - 老人说“唔好记住”。
3. 在 Firebase emulator 上跑 v1 管线，测以下各项：
   - 编造的事实数；
   - 事实抽取的精确率；
   - 跟进日期换算的正确率（香港时区）；
   - 安全场景的内容有没有进入任何一层记忆；
   - 敏感内容有没有被正确标记；
   - 按分层共享策略运行时（基本事实共享，其余各 agent 私有），某个 agent 的私有记忆有没有出现在其他 agent 的 prompt 里；
   - 删除后是否不再注入；
   - Rule-based 组是否零抽取、零注入。
4. 记录每段对话的 token 用量和延迟。

验收阈值：
- 编造事实为 0；
- 记忆条目准确率 ≥95%；
- 跨 agent 私有记忆泄露为 0。

输出：测试代码，加上 `docs/dev-reports/T4-memory-acceptance-YYYYMMDD.md`。报告里每项指标占一行，写结果、阈值、是否通过。

## T5 实现 C04 模型版本记录（小改动，分支 `feature/model-logging`）

已定方案：继续用 DeepSeek 官方 API（`deepseek-chat`），模型版本无法锁定，所以每次调用都要记录返回的 `model` 字段。

1. 找出所有调用 LLM 的地方，列成表。包括对话生成、记忆抽取、每周小结、「問下呢篇」、安全标记等。
2. 每次调用后写一条日志，字段包括：
   - 时间（UTC）；
   - 调用类型；
   - agent；
   - 研究编号；
   - 请求的模型名；
   - 返回的 `model` 字段；
   - prompt 和 completion 的 token 数；
   - 延迟；
   - 是否出错。
   日志写到独立的集合（例如 `llm_calls`），不要混进对话集合。
3. Rule-based 组不应产生任何“对话生成”类日志。如果它有安全标记之类的非生成调用，照常记录，并标明调用类型。
4. 写测试，在 emulator 上验证每一类调用都会留下日志。
5. 不合并。开一个 PR 草稿，描述里写 `SPEC:C04`。

输出：PR 草稿链接，加上 `docs/dev-reports/T5-model-logging-YYYYMMDD.md`。报告写调用点清单、日志字段和测试结果。
