# 0072：本机看板的总览在组别旁边显示整份每周问卷做完没有，每人页显示每日心情数值（取代 0061）

- 日期：2026-10-21
- 状态：已采纳（Junyu 10/20 定，decisions-log 10/20 第 66 条；10/21 确认）
- 影响范围：不影响参与者。所有 cohort × 两组：App、Functions、Firestore 规则都不改，老人看到的完全一样。只改研究员在自己电脑上用的看板
- 相关代码：分支 `claude/zealous-fermat-8rgqtg-dashboard`（PR #142）；`tool/dashboard/`
- 取代：决策 0061。0061 第 3 条「结局数据」里的两点改了（见下面第 1、2 条），其余做法照旧，在第 5 条重抄一遍。以后以本记录为准。

## 背景

0061 为了盲法定了两条限制：总览页的「每周问卷」只看 Weekly PR 这一部分，每日心情只显示「有没有记」。Junyu 10/20 第 66 条改了这两条（10/21 确认）：她要照着看板催问卷、跟进参与者。只看 Weekly PR，看不出 DJG-ES、PGIC 有没有做，没法照着催；只知道「记了心情」，跟进时不知道老人这几天心情怎样。

## 决定

1. **总览页：整份每周问卷做完没有，和组别在同一行。**
   - 每人一行。每一周一格，看那一周问卷包里的**每一部分**：
     - 第 1 至 3 周：DJG-ES、Weekly PR、PGIC；
     - 第 4 周：Weekly PR、PGIC；
     - 第 5 至 7 周：只有 PGIC（按整天开关，见决策 0067）；
     - S12（社交接触）开着时，第 1 至 4 周也算它。
   - 每一部分都做完，才算「完成」。状态有四种：未开始、未做完、已过时间、已完成。未做完和已过时间后面写做完了几部分，例如「2/3」。
   - 「做完」的标准和服务器一样（`functions/weekly_schedule.js`）：DJG-ES、S12 是提交了；Weekly PR 是做完或跳过；PGIC 是有作答时间。服务器看 PGIC 的分数在不在，看板不读分数；App 存分数时同时存作答时间，所以结果相同。
   - 窗口（几号开、几号关）也调用服务器的同一份代码。
   - 第 8 周 App 里还没做，照服务器写「未做」，不另外编规则。
   - **只看做没做完**。不读答案，不读分数。
   - 每人页也显示同样的每周问卷状态，并列出每一部分做没做。
2. **每人页：每天的心情数值。**
   - 「每日」表的心情一列，显示那天记的心情数值：1 好唔開心、2 唔係幾好、3 一般般、4 幾好、5 好開心（和 App 首页的五个脸一样）。
   - 一天记了几次，全部列出，第一次记的放最前（分析用的就是第一次，`is_primary`）。
   - 心情数值**只在每人页**。总览、今天要做、结局完成率、导出的 CSV 都没有。CSV 照旧只有「记了心情的天数」。
3. **盲法取舍（第 66 条接受）。**
   - 0061 原来的规矩是：任何页面都不把结局和组别放在一起。
   - 现在总览页的组别和整份问卷完成状态在同一行，Junyu 能按组看出谁没做完结局问卷（DJG-ES、PGIC、S12）。每人页的心情数值也和组别在同一页。
   - Junyu 接受这个取舍。理由：要照着看板提醒参与者做问卷、跟进没做完的人和情绪低的人，一个人的各部分要在同一处看到。
   - 能看到的只是「做没做完」和每日心情。问卷的答案和分数照旧读不到。
4. **仍然不读、不显示的（照 0061，测试守住）：**
   - 问卷答案和分数（DJG-ES、PGIC、S12、Weekly PR 的各题、check-in 的回答、W4 纸本的答案和分数）；
   - 对话原文；
   - 分配序列（`randomization_sequences`）、`randomization_state`、`sequence_versions`；
   - 分配日志（`arm_assignment_log`、`pilot_assignment_log`）；
   - 改组记录（`correctArm` 写在分配日志里的那一行，和用户、登记记录上的改组时间）。
5. **其余照 0061：**
   - 本机网页，只在 `127.0.0.1` 打开，不部署到网上；
   - 用只给看板用的只读服务账号（`roles/datastore.viewer`）；启动时检查，钥匙能写 Firestore 就拒绝启动；
   - 白名单：只许读列出来的集合，每次只取列出来的字段；
   - 每个返回给网页的结果都先过检查，发现答案类字段就整页报错。心情数值只在每人页、只在「每日」表里放行；
   - 看板程序不写 Firestore。「確認處理」「標記誤觸」由 Junyu 用自己的 App 账号登录，经现有服务器入口写；
   - 对话原文不进看板。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 照 0061：总览只看 Weekly PR，心情只显示有没有记 | 催问卷、跟进要看整份和心情数值；第 66 条改了 |
| 总览只放整份问卷完成，不放组别 | 第 66 条定在同一行 |
| 心情数值也放进总览或 CSV | 第 66 条只说每人页。CSV 带组别，还会存到硬盘，要的话另定 |
| 每周问卷显示分数或答案 | 不需要；催问卷只要知道做没做完 |

## 后果

- 对研究：
  - 老人那边不变，两组的 App 一样。
  - 非盲的研究员（Junyu）能按组看到每周问卷的完成情况和每日心情。风险是两组催得不一样。建议：照「今天要做」名单和每天 10:00 的提醒邮件催，两组同样对待。
  - 问卷答案、分数和分配数据照旧读不到。
  - 不用改注册、protocol、ICF、HREC。
- 对开发：
  - `tool/dashboard/lib/fields.js`：`users/{uid}/daily_mood` 多读 `mood`、`is_primary`、`entry_seq_today`；`mood` 只在每人页的 `days[].moods[].mood` 放行，别处照旧拦下；
  - 总览每周读四个部分的「完成」字段（照旧不读答案），规则调用 `functions/weekly_schedule.js`；
  - 测试改为：心情数值出现在每人页，不出现在总览、今天要做、完成率和 CSV；答案、对话、分配字段照旧哪里都不出现；
  - 说明 `docs/release/ops-dashboard-local.md` 跟着改。
- 对论文：方法部分写研究员怎样跟进时，可以加一句：非盲的研究员在只读看板上看各人的问卷完成情况和每日心情，用来提醒和跟进；看板读不到问卷答案和分数。局限部分可以提「研究员知道组别，也看得到完成情况」。
