# 0015：签到 B 和回忆 B 每次提交算一次会话，提交后弹 Brief PR

- 日期：2026-10-04
- 状态：已采纳
- 影响范围：phase_b × 规则组（签到、回忆）
- 相关代码：`lib/features/brief_pr/data/rule_submission_flow.dart`

## 背景

Brief PR 是聊完之后的问卷：离开聊天页、本次用户说了 ≥2 句、不是因危机结束时弹出。Hybrid 组的签到和回忆是聊天，会弹；规则组的签到是一张表单、回忆是一个输入框，都不是聊天，所以从来不弹，也不写 `sessions`。两组的结局测量和使用量记录口径因此不同。

## 决定

- 签到 B、回忆 B **每提交一次 = 一次会话**：写一条 `sessions`（`kind: agent`，`moduleId` 和 A 组相同：`m2_check_in`、`m3_reminiscence_w{N}`）和一条 `turns`（`llmStatus: rule_based`）。
- 提交后弹 Brief PR，规则和其他页面一样：危机（acute）结束的不弹；每个陪伴者第一次弹出没有「跳过」按钮。
- 「≥2 句」这条只适用于聊天页。表单式页面一次提交就算合格，因为它没有「轮」的概念。
- 首页「今個星期傾咗 N 次」统一从 `sessions` 统计，不再用签到事件单独补 B 组。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 规则组页面不弹，分析时只用两组都有的页面（通通） | 规则组的 Brief PR 数据会少很多，而签到是使用最频繁的页面 |
| 规则组也要求「≥2 次输入」 | 表单式页面一次提交就结束，没有第二次输入 |

## 后果

- 对研究：
  - 两组每个模块都有 Brief PR，但触发门槛不同：聊天页 ≥2 句，表单页 1 次提交。Methods 里要写明。
  - Brief PR 的题目（「小欣明白我」等）对一张表单是否适用，需要研究上判断，可能需要在局限里提一句。
- 对开发：顺带把签到 B 的安全处理改成和其他页面一样走 `DistressRouter`（acute 打开危机页，moderate 显示支援底板）。之前签到 B 只弹一个写死热线的对话框，acute 也不进危机页，和「两组安全流程一致」不符。
- 对论文：Methods（结局测量的触发时点）。
