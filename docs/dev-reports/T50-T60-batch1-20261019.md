## 一、C：序列版本的存法（等 Junyu 批）

4. **上传加三道防线：**

   - v2 已经有人分配就拒绝再上传；v2 的指纹和 v1 一样（用了同一个种子）也拒绝。**生成时一定要换新种子。**

## 五、第 1 节 (5)：模型每次收到什么（按代码）

**结论：服务器没有任何地方把 `agent_contexts.shortTermBuffer` 放进聊天模型的输入。**

Hybrid 组每次调用，模型收到四样东西：

1. 人设提示词；
2. App 附带的背景：
   - 心情分；
   - 回忆往周的摘要、签到时的回忆片段；
   - 通通的兴趣和文章；
   - 记忆：记忆 v1（Phase B）是服务器的记忆条目（事实、跟进、每日摘要）；旧的 v0 是不超过 500 字的滚动摘要。
3. 热线规则；
4. 本页这次打开的对话。

缓冲区的原文只进两个旁路调用：App 的 v0 摘要、服务器 v1 的事实抽取。它们的产出才变成以后放进提示的记忆。

另一点：同一页里超时或换陪伴者，会话记录会结束，但本页的对话历史不清空。所以「本页这次的对话」可能跨两个记录会话。
