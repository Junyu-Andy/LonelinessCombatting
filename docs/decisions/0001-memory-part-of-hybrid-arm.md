# 0001：跨会话记忆属于 Hybrid 组干预包，规则组没有记忆

- 日期：2026-10-01
- 状态：已采纳
- 影响范围：phase_b × 两组；phase_a（如果采用 v1）
- 相关代码：v1 记忆（已合并，未上线）

## 背景

Phase B 的对等设计是「只有回应生成后端不同」。v1 记忆只给 Hybrid 组用，规则组没有。这样一来，两组 PR 的差别里会混进「被记住」这个因素，所以需要事先说明：记忆算不算 LLM 增量的一部分。

## 决定

算。从老人随口说的粤语里提取事实，本身就要靠 LLM，所以「理解 + 记住 + 生成」整体作为 LLM 增量。规则组不加记忆。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 规则组加模板式记忆（抽取仍用 LLM，用模板说出来） | 规则组的数据也要发给 LLM 处理，ICF 要改；另外要开发约 2–4 天；模板句子容易显得生硬 |
| 三组拆解设计 | N = 72，样本量不够 |

## 后果

- **对研究：**
  - 注册和 protocol 的干预描述要补上记忆；
  - Hybrid 组 ICF 要写清记忆怎么查看和删除；
  - 操纵检验加上「记忆回调次数」；
  - 「我的資料」入口要做到两组一致。
- **对开发：** 见 `docs/dev/memory-and-entry-spec.md` 的 P0 部分，约 4–6 天。
- **对论文：**
  - Methods 写明后端包含记忆；
  - Limitations 写明生成和记忆的贡献无法拆分；
  - 提一句后续可以用拆解设计来区分。
