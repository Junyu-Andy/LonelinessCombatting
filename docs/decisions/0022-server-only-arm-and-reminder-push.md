# 0022：分组字段只由服务器写、参与者不能删自己的用户文档；行动计划提醒由服务器定时推送（开关默认关）

- 日期：2026-10-07
- 状态：提议中（随 T13 的 PR 草稿，合并即采纳）
- 影响范围：phase_b × 两组（规则部分对所有 cohort 生效）
- 相关代码：分支 `fix/misc-prelaunch`（`firestore.rules`、`functions/reminders.js`、`functions/index.js` `dispatchReminders`、`tool/prelaunch_config.js`）

## 背景

决策 0003 定了「客户端不能写分组相关字段」，但 Firestore 规则只保护了 `armAssignmentMode/By/At`：参与者本人建档时可以直接写 `arm`，分组为空时也可以自己填 A 或 B；`strataCell` 不受保护；本人还能删掉自己的用户文档，再建档就会被重新抽签（T1 报告 C01）。

另外，行动计划（Action Loop）的跟进提醒只写进了 `users/{uid}/reminders`，从来没有发出去，两组都收不到（T1 报告 C07）。

## 决定

**一、分组字段**

1. `arm`、`strataCell`、`armAssignmentMode`、`armAssignedBy`、`armAssignedAt` 只有服务器（`assignArm`）能写。客户端建档时不能带这些字段；之后不能改、不能删。重复写入同样的值不算改动，所以 App 现有的资料保存不受影响。
2. 客户端不能删除自己的 `users/{uid}` 文档。退出研究、整人删除走服务器端（T11 负责的整人删除脚本，用管理员权限）。

**二、行动计划提醒**

1. 发送方式：服务器定时函数 `dispatchReminders`，通过 FCM 推送到参与者自己的手机（`fcm_tokens`）。不用手机本地通知。
2. 时间：香港时间 08:00–21:45，每 15 分钟一次。到时间的提醒在下一次运行时发出；晚上到时间的，第二天 08:00 发。
3. 不发的情况：已经超时 12 小时以上（避免开关打开时一次推出一大堆旧提醒）；当天开了「今日休息」；对应的行动计划已经删掉或已经回答过「件事點呀？」。
4. 失败重试：一台手机都没发成功，下次运行再试，最多 3 次。每条提醒最多发一次（宁可漏一条，也不重复推）。
5. 文案：标题「陪住」，内容「件事點呀？」，都是现有文字。**不发**计划原文（`bodyZh`），免得老人自己写的内容出现在锁屏上。
6. 两组完全一样，不看分组，不调用 LLM。
7. 开关：`app_config/reminders.m7FollowupPushEnabled`，默认关（文档不存在 = 关）。研究侧确认后在控制台打开。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 分组字段只防「改」，允许本人建档时写 | 就是现在的漏洞 |
| 允许删用户文档，但服务器另记一份分组台账 | 改动更大；而且 App 本来就没有删账号功能，删除应走研究者流程 |
| 提醒用手机本地通知（`flutter_local_notifications`） | 要加原生依赖，Android/iOS 都要单独测；卸载重装或换手机会丢；服务器已有 FCM 推送可以复用 |
| 推送里带计划原文 | 老人自己写的内容会出现在锁屏和 Google 的推送通道里；需要研究侧决定 |
| 晚上也照原时间发 | 计划时间 +24 小时可能落在半夜 |

## 后果

- 对研究：随机化完整性的漏洞堵上了，参与者无法自选组别或删档重抽。行动计划提醒打开后，两组的干预剂量（提醒次数）会增加，打开日期要记进 `STUDY_CHANGELOG`。推送前后的行为可以从 `events` 里的 `m7_reminder_sent` 对上。
- 对开发：上线前要部署新规则和新函数；参与者想删除全部数据时只能由研究者用脚本处理（T11）。
- 对论文：方法部分写明分组只由服务器写；行动计划提醒的发送时间窗、超时不补发的规则。
