# 第 2 批（T50 = A、T55 = F）：小欣页一个聊天窗口，check-in 对话化，规则组小欣聊天

日期：2026-10-19。分支 `claude/zealous-fermat-8rgqtg-batch2`（从 main `3d36112` 开，PR #128 草稿）。范围：1020 第 A 节、第 F 节 (1)(2)(3)(4)(6)；不含 F (5) 推送。

## 结论

- 做完了。新行为全部在远程开关 `app_config/feature_flags.checkInChatV2Enabled` 后面，**默认关**，关时旧页面一字不变。10/21 构建按 1020 第 3 节设为开。
- 开关开时：两组撳小欣卡片都进**同一个聊天窗口**。当天还没做 check-in，就自动一问一答：问题、按钮、顺序两组完全一样，不由 LLM 写。
- 规则组：小欣的回应全部来自模板，**全程零 LLM 调用**（测试里装了“一叫就报错”的假模型）。服务器那道拒绝规则组的防线也没动，另有测试证明新提示词 key 同样被拒。
- Hybrid 组：两句回应由 LLM 写，用新提示词 `siu_yan.v3`（只比 v2 多一节 check-in 规则，旧文件不动）。
- 规则组以前没有小欣聊天，现在有：做完 check-in 再进来，开场 SY0，之后从 SY1–SY6 轮流回一句；当天心情低落时用 SN1–SN4。
- 全部 Flutter 测试（六套）和相关 Functions 测试通过；`flutter analyze` 没有新错误。
- 老人看到的文字全部照 1020b 第四节草稿，等你在截图里定。

## 1. 老人会看到什么

### 1.1 当天还没做 check-in（两组相同）

1. 小欣说 Q0：中午前「早晨！想問下你尋日嘅情況，幾條就得。」，12:00 起「早晨」换成「你好」。
2. Q1「尋日成日整體過得點？」——按钮：好開心／幾好／一般般／唔係幾好／好唔開心／唔想答。
3. Q2「尋日有冇同人傾過偈？」——冇／少少／幾多／好多。
4. Q3「尋日有冇咩特別事？」——冇／一啲小事／一件大事。
5. 选“一啲小事”或“一件大事”才出 Q3b「想講下係咩事嗎？打字講都得，唔講都得。」——输入框，上面一个「唔講住」按钮。
6. 小欣回应一（见 1.3）。
7. Q4「今日有咩打算？想講就講，唔講都得。」——输入框和「唔講住」，没有选项。
8. 小欣回应二（见 1.3）。
9. Q5「想訂個小計劃嗎？」——好呀（打开现有的行动计划页，回来继续）／唔使喇。
10. Q6「多謝你同我傾，聽朝再問候你。」之后输入框照常，可以继续聊。

问按钮题时下面只有按钮，没有输入框。按钮至少 52 像素高，窄屏和特大字时自动换行（文字扫描在 320／360／375／390 宽 × 字体 1.0／1.3 都没有溢出）。

### 1.2 当天已经做过

- 规则组：开场 SY0「今日 check-in 做咗喇，想再講啲咩都得。」
- Hybrid 组：开场一句由 LLM 说（提示词里的 `[開場·check-in 已做]` 规则）；LLM 失败时也用 SY0。
- 之后是普通聊天。

### 1.3 小欣的回应

| 位置 | 规则组 | Hybrid 组 |
|---|---|---|
| 回应一 | 按 Q1：好開心 X1、幾好 X2、一般般 X3、唔係幾好 X4、好唔開心 X5（每档 4 条，近 3 次不重复）；唔想答用 XG | LLM 按 Q1–Q3（和 Q3b）回一两句 |
| 回应二 | Q4 有答 R4a；唔講住 R4b | Q4 有答：LLM 最多提一两个去处或做法，不催促；唔講住：**也用 R4b 固定句，不调 LLM，不给建议** |
| check-in 后聊天 | SY1–SY6 轮流（整组轮完再从头）；当天 `daily_mood` 最近一笔是唔係幾好或好唔開心时用 SN1–SN4 | 照旧 LLM 聊天（想法练习邀请、跨伙伴转介、记忆都保留），提示里附上今日答案，叫它不要再问 |

### 1.4 安全

- Q3b、Q4 和之后打的每一句，两组都过同一个安全检测（输入点 `chat_check_in`；`lib/core/safety/` 和词库没改）。
- 命中时**不出模板**，照现有流程：moderate 弹支援页，关掉后继续下一题；acute 显示危机句、打开危机页、会话按 crisis 结束，**check-in 停在那里不再问**（记 `stopped_by_safety: true`）。
- 按钮答案不是老人的原话，规则组不检测。Hybrid 组在没打字时把按钮文字当作这一轮发给模型，这样模型的回复仍照常过安全检测；会被发出去的只有 Q3 的三个按钮和「唔講住」，测试确认它们不命中任何词。

### 1.5 Brief PR（A (2)）

- 做完 check-in 算一次有效会话。继续聊仍是同一会话，按现有规则结束（收尾按钮、返回、30 分钟、切换伙伴、危机）。
- 会话 v2（`sessionBriefPrV2Enabled`）开着时：结束后**不弹问卷**，只在列表页（和首页，若开了 `briefPrHomeBannerEnabled`）出邀请卡。邀请卡有「今次唔評」，问卷每屏有「唔評住」，两组同一套页面，没有分组判断——测试里规则组按「唔評住」，记录为 `skipped`。
- 会话 v2 关着时沿用旧的“离开聊天页时按条件弹出”。10/21 设定应是开着。

## 2. 记录：`users/{uid}/check_in_responses`

每次 check-in 一份。答第一题时建立，之后每答一题合并写一次，中途离开也保留已答部分。旧表单写的行不变（没有 `flow` 字段）。新行字段：

| 字段 | 内容 |
|---|---|
| `arm` | `A` / `B` |
| `flow` | `chat_v2` |
| `schema_version` | `2` |
| `copy_version` | 问题文字版本 `1020b-s4-20261019-draft` |
| `date_iso` | 手机日期 `YYYY-MM-DD`（和旧行同名） |
| `study_day` | 研究第几天（W0 = 0；没有 W0 时为空） |
| `study_week` | 研究周（第 1–7 天 = 1） |
| `session_id` | 所属会话 |
| `answers.Q1` | `question_id`、`value`（very_happy / good / so_so / not_good / very_unhappy / prefer_not）、`label`（按钮字）、`score`（5…1，唔想答为空） |
| `answers.Q2` | `question_id`、`value`（none / a_little / quite_a_bit / a_lot）、`label`、`index`（0–3） |
| `answers.Q3` | `question_id`、`value`（none / small / big）、`label`、`index`（0–2） |
| `answers.Q3b` | `question_id`、`skipped`、`text`（只在问过时有） |
| `answers.Q4` | `question_id`、`skipped`、`text` |
| `answers.Q5` | `question_id`、`value`（yes / no）、`label` |
| `questions_shown` | 按顺序显示过的题号，如 `[Q0, Q1, Q2, Q3, Q3b, Q4, Q5, Q6]` |
| `response1_id` | 规则组 `X1-1`…`X5-4` 或 `XG`；Hybrid `llm`（失败 `llm_fallback`）；命中安全 `none_safety` |
| `response2_id` | `R4a`、`R4b`（Hybrid 唔講住也是 `R4b`）、`llm`、`llm_fallback`、`none_safety` |
| `stopped_by_safety` | acute 令 check-in 提前结束时为 true |
| `completed` | 答完 Q5 为 true |
| `created_at` / `updated_at` / `completed_at` | 服务器时间 |

- 规则组的 Q3b、Q4 原文只存在这里，不进任何模型调用（安全分类器开关开着时，两组的打字都会送分类器，这是现有安全层，两组相同）。`turns` 只记字数，和所有聊天页一样。
- 会话行 `sessions`：做完时多一个 `checkInCompleted: true`（只在为 true 时写，旧行不变）。check-in 会话 `moduleId` 是 `m2_check_in`（类型“签到”）；已做完再进来的聊天是 `siu_yan_chat`（类型“自由聊天”，≥3 条有回复才有效）。
- 事件：做完时照旧写 `check_in_submitted` 和 `m2_check_in_submitted`（首页状态行、三天未做横幅、周小结都读它），参数是答案代码，`mood` 是 Q1 分数（唔想答时没有），不含原文。规则组模板写 `rule_template_reply`（`template_id`、`pool_version`）。

### 9.3 新函数和字段

- 函数：`markSafetyFalseAlarm`（asia-east2，callable，`functions/false_alarm.js`）。参数 `{alertId}`。只认 Auth 角色 `unblinded`（和 `acknowledgeAlert` 同一条规矩），并要开关 `safetyFalseAlarmMarkEnabled` 为 true。
- 写的字段（三处一样）：`falseAlarm: true`、`markedBy`（研究员 uid）、`markedAt`（服务器时间）。
  - `safety_events/{id}`（告警指向的那条事件）；
  - `pi_alerts/{alertId}`（仪表板只读告警，不读安全事件）；
  - `users/{uid}/check_in_responses/{id}`：`flow` 是 `chat_v2`、`stopped_by_safety` 是 true、`date_iso` 是事件发生那天（香港日期）、会话编号相同（两边都有时）、陪伴者是小欣的那一行。
- 第二次按：不改原来的标记，返回 `alreadyMarked`。每次新标记写一条 `alert_audit_log`（`false_alarm_marked`）。
- check-in 行上第 4 批要读的字段：`stopped_by_safety`、`falseAlarm`、`markedBy`、`markedAt`、`completed`（名字完全照这几个）。续问那一行另有 `resumed_from`。
- `firestore.rules`：客户端建安全事件时不能带这三个字段；`check_in_responses` 行客户端建时不能带、改时不能动这三个字段（App 自己的其他字段照常写）。告警和安全事件客户端本来就不能改。
