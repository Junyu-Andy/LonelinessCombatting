# 0034：Phase A 暂停；这个仓库和 Firebase 项目只做 Phase B 和试跑

- 日期：2026-10-10
- 状态：已采纳（产品窗口 10/10 第 10 条，负责人转来）
- 影响范围：phase_a 暂停；phase_b、pilot 不变 × 两组
- 相关代码：任务单 `docs/dev-tasks/dev-tasks-1010b.md`（T21、T32 的更正）；登记表 v8 C01、C22

## 背景

10/9 第 19 条定了 Phase A 和 Phase B 用同一个构建、同期收数据，按登记编号前缀（`PA-`、`PB-`、`PILOT-`）区分研究期（T21、T32）。10/10 第 10 条改为 Phase A 暂停，以后单独开仓库和 Firebase 项目。

## 决定

1. 登记只认 `PB-`、`PILOT-` 两种前缀；`PA-` 编号登记时拒绝，和没有前缀的编号同样处理（T21）。
2. Phase A 专用部分（ADA、第 7 日问卷、Phase A 的 DJG、`PA-` 的配置）在构建里保持关闭，不再开发。代码现在不删。
3. T32（Phase A 用最终构建）里只属于 Phase A 的部分停做。和 Phase A 无关的部分（例如旧测试员数据清理脚本）是否还要，等开发窗口重排。
4. 登记表里写到 Phase A 的条目标“暂停（10/10 第 10 条）”；C22 整行暂停。
5. 决策 0026、0030（ADA）不改，也不算被取代：它们在 Phase A 恢复前不生效。
6. Phase A 以后单独开仓库和 Firebase 项目，到时另行交接。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 现在就删掉 Phase A 的代码 | 产品窗口要求现在不删；以后单独开仓库时可能要搬走这些代码 |
| `PA-` 照常登记，只是不招人 | 留着入口容易误登记，两期数据混在同一个项目里 |

## 后果

- 对研究：本项目只收 Phase B 和试跑的数据。Phase A 的方案、ICF 和 HREC 材料由研究侧另行处理。
- 对开发：T21 去掉 `PA-` 分支并加“`PA-` 被拒”的测试；T32 大部分停做；T26、T31 里“Phase A 也用”的要求不再需要单独验证，但同一构建内的代码不必拆开。
- 对论文：不涉及 Phase B 的方法；Phase A 另写。
