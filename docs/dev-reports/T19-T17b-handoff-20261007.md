## 结论

1. **T19、T17b 做完了**，合成后两套测试全过（第六节）。
2. **两个新功能都默认关**：分组开关关着时，Phase A 和试用账号照旧分到 A 组；ADA 开关关着时老人看不到 ADA。
3. **但有三处一部署就生效，不受开关控制**：
   - **账号角色改名**：旧的 `pi`、`researcher` 账号部署后**立刻失去所有研究员权限**。部署当天要给 Keran 重发 `unblinded`、给 PI 和其他人重发 `blinded`（第二节第 1 步）。
   - **发给 PI 的安全告警变短**：只剩研究编号、级别、香港时间、告警编号，不再带陪伴者、来源、输入点，因为这些能推出组别。告警照样每条都发，细节要问 Keran。
   - 分组计数器客户端不能再读写；`app_config/arm_assignment` 停用。
4. **Phase B 第一位老人注册前，必须先打开分组开关**（`meta/randomization_config.enabled`）。没打开就注册的人会被分进 A 组，而且改不了。
5. **ADA 要等 PI 书面确认截图后才能打开。**截图在 `docs/dev-reports/T17b-ada-v1-20261007-screenshots/`。

## 二、上线前要做的（按顺序）

1. **重发研究员账号角色**：`tool/provision_researcher.js --list-legacy` 列出旧角色账号，`--revoke` 后重发。Keran 用 `unblinded`，PI 和其他人用 `blinded`。
2. **PI 的 Google Cloud / Firebase 账号不要有读 Firestore 的项目权限**，PI 只用盲法导出和盲法视图。
3. **在 Google Cloud 控制台打开 Firestore 的数据访问审计日志**，留下谁读过分组和序列的记录。步骤在 `docs/release/prelaunch-checklist.md` G 节。
4. **Keran 生成并上传分配序列**，用自己选的种子；种子和序列文件交导师离线保存。`tool/prelaunch_config.js` 只检查序列已上传（打印长度和指纹，不打印内容），PI 也能跑。
5. **打开分组开关** `meta/randomization_config.enabled`，**必须在第一位 Phase B 老人注册前**。
6. HTML 随机化工具停用（清单 G 节打勾）。
7. ADA：PI 书面确认截图后，再打开 `app_config/phaseA_schedule.adaEnabled` 和 `day7OpenEndedEnabled`。

## 三、开关和配置

| 开关 / 配置 | 管什么 | 默认 |
|---|---|---|
| `meta/randomization_config.enabled` | 开：可以登记、按序列分组，`assignArm` 不再分组。关：不能登记，`assignArm` 照旧把 Phase A 和试用账号分到 A | 关 |
| `app_config/arm_assignment.randomise` | 停用。开关关着时它若为 true 会拒绝分组，免得误分 A | — |
| `app_config/phaseA_schedule.adaEnabled`、`day7OpenEndedEnabled` | ADA 和第 7 日开放题 | 关 |
| `app_config/phaseA_schedule.adaTimepoints` | 第 1 天短版 B+D；第 7–9 天全版 | 见左 |
| `app_config/phaseA_schedule.adaHelpPhone` | 求助电话号码。没填时按钮照样显示，但不拨号，提示"研究員之後會打電話俾你"（草稿） | 空 |
| `app_config/phaseA_schedule.adaDay7ReminderTimeOptions`、`adaDay7ReminderDefaultTime`、`adaDay7ReminderHours` | 提醒时间选项（10/14/17/19 点）、默认 10:00、24 小时后再提醒 | 见左 |
| `app_config/phaseA_schedule.day7FlowMinutes` | 流程开头显示的预计时间，要等试跑 | 空（显示占位） |

推送文字都是【占位】，定稿前服务器不发。

## 四、要研究侧 / PI 定的事

**分组（T19）：**

1. 老人注册后、研究员登记前，App 显示规则组界面（决策 0004），这段时间的数据计入还是剔除，干预从哪天算。建议当天登记，并让老人重开 App。这段时间服务器还分不清 Phase A 和未登记的 Phase B，所以不拒绝 LLM 调用；T21 加上研究期后可以拒绝。
2. 整人删除时，分配日志和已用的序列位置保留（登记记录删除）；审计日志的保存期写进 DMP。
3. 研究编号格式：现在接受 2–12 位大写字母、数字和"-"。
4. 阿珍/阿伯由登记写入，但老人在 App 里还能改（锁住会让老人保存整份资料失败）。
5. protocol 和 SAP 里的随机化方法要按新做法改写。
6. PI 告警只剩研究编号后，PI 收到告警怎么跟进（向 Keran 要细节）。
7. 告警仍挡不住的地方：Hybrid 组多一种来源（AI 回复扫描），两组告警次数可能不同。

**ADA（T17b）：**

8. 老人看得到的草稿文字：两句推送、提醒时间选项、流程说明、求助弹窗。
9. 求助电话号码。
10. 流程预计时间（试跑后定）。
11. Phase A 的研究编号由谁、什么时候发。现在 Phase A 多数人没有编号，研究员页面这一栏暂时为空。
12. 研究员电话代填时遇到危险发言的处理流程。现在服务器用词库检查，命中写安全事件、通知 PI，研究员屏幕上弹提示，老人那边不弹危机页。
13. 电话补做的数据要不要分开报告。
14. "第 1 次到访"现在按账号创建日算。Phase A 若也走研究员登记（T21），可以改用登记日。
