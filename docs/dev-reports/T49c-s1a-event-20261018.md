# T49c：通通给出固定回复 S1a 时记一条事件（2026-10-18）

任务单：`docs/dev-tasks/dev-tasks-1018.md` §C（PR #114）。分支 `feat/t49c-s1a-event`，PR 草稿。

## 结论

- 老人问到要上网查的事、通通显示固定回复 S1a 时，App 在 `users/{uid}/events` 记一条 `s1a_fixed_reply`。**两组都记，记法一样。**
- 新开关 `app_config/feature_flags.s1aEventLogEnabled`，**默认关**。关着什么都不写。**要用时在 Firebase 控制台把它设成 `true`。**
- 事件里**没有老人原话，也没有匹配到的词**。
- 不改 S1a 文字，不改任何干预内容，搜一搜仍然关闭。老人看到的东西完全不变。
- **待核的答案：代码里是逐字输出。** Hybrid 组遇到这类问题，S1a 不经过 LLM，屏幕上显示的就是 S1a 原文（见第 3 节）。
- 导出：每周过程数据导出（`exports_process/`）多一个文件 `event_counts`，按人给次数；manifest 里按组给合计。锁库后的分析导出不用改（第 4 节）。
- 运营看板不显示。

## 1. 什么时候记

只在 S1a **真的显示出来**时记，每显示一次记一条。条件和 S1a 本身一样：

1. 开关 `searchOffReplyEnabled` 开着（S1a 本身的开关，默认关）；
2. 搜一搜关着（`webSearchEnabled` 不是 `true`）；
3. 不在「問下呢篇」文章模式；
4. 老人这句话命中 `TungTungSearchIntent` 的关键词；
5. 安全检测没有命中（命中就走原来的安全流程，不出 S1a，也不记）。

再加上本任务的开关 `s1aEventLogEnabled` 开着，才写这条事件。

页面里用到 `TungTungSearchIntent` 的地方：

| 位置（`lib/features/curious_companion/presentation/pages/tung_tung_page.dart`） | 做什么 | 记不记 |
|---|---|---|
| 第 125 行 `_isSearchOffQuestion` | 只判断「是不是要上网查的问题」 | 不记 |
| 第 351–362 行（Hybrid 组 `_send`） | 判断后调用 `_replySearchOff`，然后 `return` | — |
| 第 600–605 行（`_replySearchOff`） | 把 S1a 放上屏幕，**紧接着记事件**（`arm: A`），再记这一轮（turn） | 记一次 |
| 第 731–736 行（规则组 `_sendRuleBased`） | 用 S1a 替换规则模板 | — |
| 第 759 行 | S1a 放上屏幕后**记事件**（`arm: B`），再记这一轮 | 记一次 |

判断和记 turn 的地方都不写这条事件，所以一次 S1a 只有一条，不会两次。

## 2. 事件字段

写法和其他会话事件一样（`ChatSessionRecorder.logEvent` → `AnalyticsService.logEvent` → `users/{uid}/events`）。

| 字段 | 内容 |
|---|---|
| `name` | `s1a_fixed_reply` |
| `params.agentId` | `tung_tung` |
| `params.sessionId` | 这次会话的编号（和 `sessions`、`turns` 同一个） |
| `params.arm` | `A`（Hybrid）或 `B`（规则组） |
| `params.matchedVersion` | 关键词和文字的版本 `TungTungSearchIntent.version`（现在是 `2026-10-10-s1a`） |
| `params.clientTime` | 手机时间（ISO 文本） |

`AnalyticsService` 自己会再带上通用字段（服务器时间 `timestamp`、`locale`、外层 `arm` 等），和所有事件一样。

研究编号不写在事件里：事件在 `users/{uid}` 下面，导出时按 uid 对到研究编号。

原来就有一条 `tung_tung_search_off_reply`（只有 `arm` 和 `version`，没有会话编号，不受开关控制）。本任务没有动它，见第 6 节。

## 3. 待核：Hybrid 组 S1a 是逐字还是 LLM 改述

**代码里是逐字输出：Hybrid 组命中后调用 `_replySearchOff` 就 `return`，不调用 `llm.send`，屏幕上显示的是 `TungTungSearchIntent.replyS1a` 原文。**

- `tung_tung_page.dart` 第 351–362 行：命中且安全检测无事 → `await _replySearchOff(...)` → `return;`。LLM 调用在第 457 行 `core.llm.send(`，这一轮走不到。
- `tung_tung_page.dart` 第 600 行：显示的文字是 `TungTungSearchIntent.reply(...)`，即 `tung_tung_search_intent.dart` 第 59 行的 `replyS1a`。
- 测试 `test/tung_tung_arm_b_test.dart` 的 Hybrid 用例确认：两次 S1a 都没有调用 LLM。

`functions/prompts/tung_tung.v2.txt` 模式 B 第 5 条（第 50–52 行）只在**没有出 S1a** 的时候起作用：开关 `searchOffReplyEnabled` 关着、关键词没命中、或者安全检测有命中走了 LLM。那时是 LLM 用自己的话说「查唔到、问下屋企人或社工」，不是 S1a 原文，也不会记这条事件。

## 4. 导出怎么拿到次数

- **每周过程数据导出**（`functions/process_export.js`，开关 `meta/blinding_config.processExportEnabled`，给 `unblinded`）：原来不读 `events`。现在多一个文件 `exports_process/{日期}/event_counts.ndjson`，每位 Phase B 参与者一行：`researchId`、`arm`、`name`（`s1a_fixed_reply`）、`count`。只数行数，不读事件内容。`manifest.json` 多一个 `eventCountsByArm`，如 `{"s1a_fixed_reply": {"A": 12, "B": 9}}`。
- **锁库后的分析导出**（`tool/analysis_export.js`）：`events` 表本来就按事件名通用导出（`researchId`、`arm`、`name`、`ts`，没有 params）。`s1a_fixed_reply` 自动在里面，按 `researchId` / `arm` 数 `name` 即可。**不用改。**
- 注意：开关打开前的 0 是「没记」，不是「没出现过」。

## 5. 测试

- `test/tung_tung_arm_b_test.dart` 加两个用例（一个在 `PHASE_B=true FORCE_ARM=B` 跑规则组，一个在默认包跑 Hybrid 页）：
  - 事件开关关：S1a 显示了，没有 `s1a_fixed_reply`；
  - 事件开关开：再问一次，多一条，params 只有上面五个字段，没有原话、没有「天氣」；
  - 普通一句话：不多记；
  - S1a 开关关、事件开关开：没有 S1a，也不记；
  - 规则组全程不调用 LLM；Hybrid 组 S1a 那两轮不调用 LLM。
- `test/phase_b_flags_test.dart`：新开关默认关、只认 `true`。
- `functions/test/t30_server_emulator_test.js`：过程数据导出的 `event_counts` 按人、`eventCountsByArm` 按组正确，不带事件参数。
