# 0002：两组用同一个仓库、同一个安装包，按组切换页面

> 补记（2026-10-04）：这个决定当时在对话里做出，代码已合并。按模板补写，内容以当时的讨论为准。

- 日期：2026-09-29
- 状态：已采纳
- 影响范围：两组 × 所有 cohort
- 相关代码：PR #23（`Arm.of` / `ArmGate`、`PHASE_B` 编译开关）

## 背景

规则组要和 Hybrid 组分开实现。当时问过：要不要为规则组单开一个代码库或一个 App。

## 决定

同一个仓库、同一个安装包。每个模块的 A/B 实现放在一起，用 `ArmGate` 或 `Arm.isA` 按用户的 `arm` 字段切换。正在进行的试验和新功能用不同的 git 分支并行开发，通过 PR 合进 `main`。

## 考虑过的其他方案

| 方案 | 为什么没选 |
|---|---|
| 规则组单独一个仓库或 App | 两边改一处就要同步两处，界面很容易走样，两组差异就不再只是「后端不同」；参与者可能从安装包看出自己在哪组；安全检测难以保证两组完全一致 |

## 后果

- 对研究：保证界面、安全流程两组一致；参与者从外观上看不出组别。
- 对开发：每个模块要写两套实现；服务器另加一道防线，B 组调用 LLM 一律拒绝。
